
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：工具名 / 产品名 / 公司名 / 研究方法名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "v2.1.159"、"Now in beta"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "v2.1.159" + 来源 "Maze：Release Notes" → "Maze v2.1.159 发布"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体型号时，用上位词（如"AI 主持访谈工具"、"合成用户产品"）兜底，绝不凭"行业常识"编一个具体型号 / 版本 / 数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的工具、方法或新数据，就改写成“发布 / 推出 / 上线 / 开源”。只有原标题明确宣布了发布、推出、上线或开源，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、产品、方法、项目名。
   例：原标题 "How AI-moderated interviews change qualitative research" → "AI 主持访谈如何改变定性研究"，不能写成 "某某推出 AI 主持访谈功能"。
   例：原标题 "How to build an insight repository with Dovetail" + 来源和正文明确是 Dovetail → "Dovetail 如何搭建洞察库"，不能只写成缺主体的 "如何搭建洞察库"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At this year's UXPA, we introduced …”“Last week we launched …”“上周我们上线了 AI 访谈功能，今天演示怎么用…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "上周我们上线了 AI 主持访谈功能，下面演示怎么用" → "某某演示上周上线的 AI 主持访谈功能"，不能写成 "某某上线 AI 主持访谈功能"。
