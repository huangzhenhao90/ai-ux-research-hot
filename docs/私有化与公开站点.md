**为什么要两个仓库**：私有仓库的 GitHub Pages 需要付费套餐（Pro / Team）。「私有源码 + 公开站点仓库」是不付费也能做到的办法，
站点仓库里的东西就是读者浏览器里本来就能看到的。

**站点仓库里不会有**：采集器与评分代码、提示词、`config/`、`data/`（条目原始状态、评分、社招抓取状态）、
`data/social/manual.yaml`（Boss 直聘 / 社群的手动收录，含私有备注）、工作流、密钥。
推送前 `scripts/check_public_output.py` 会逐项检查（见下面「防漏」），不过就不推，公开站点保持上一版。

## 一次性设置（你来做，约 15 分钟）

**顺序很重要：先让新站点上线、确认能打开，最后一步才把源码仓库转私有。** 这样中间站点不会下线。

1. **新建公开仓库**：GitHub → New repository → 名字随意（下面以 `urhot` 为例）→ Public → **不要**勾选 README / .gitignore / License（让它是空的）。
   - 网址由仓库名决定：`https://huangzhenhao90.github.io/urhot`。想保持现在的网址不变，见下一节「想保持网址不变」。
2. **生成一对 deploy key**（在你自己电脑上）：
   ```bash
   ssh-keygen -t ed25519 -C "urhot-deploy" -f urhot-deploy -N ""
   ```
   - 公钥 `urhot-deploy.pub` 的内容 → 新仓库 Settings → Deploy keys → Add deploy key → **勾选 Allow write access**。
   - 私钥 `urhot-deploy` 的**全部内容**（含 BEGIN / END 两行）→ 源码仓库 Settings → Secrets and variables → Actions → New repository secret，名字 `SITE_DEPLOY_KEY`。
   - 做完把这两个文件从电脑上删掉。deploy key 只对这一个仓库有写权限，泄露了也动不了别的。
3. **源码仓库加变量**：同一页的 Variables 标签 → New repository variable：`PUBLIC_SITE_REPO` = `huangzhenhao90/urhot`。
4. **改站点地址**：编辑 `config/site.yaml`，把 `siteUrl` 改成 `https://huangzhenhao90.github.io/urhot`，
   `crawlerName` 括号里的关于页地址也同步改（它会出现在采集器的 User-Agent 里）。合并到 `main`。
   - 发布脚本会核对「产物里的子路径」和「公开仓库名推出来的 Pages 路径」，对不上就拒绝推送，不会发出一个样式全丢的站。
5. **手动跑一次 Update**：Actions → Update → Run workflow（`dry-run` 即可）。日志里「发布到公开站点仓库」那步显示 `✓ 已推送 … 个文件`，
   新仓库里就有了 `gh-pages` 分支。
6. **开 Pages**：新仓库 Settings → Pages → Source 选 **Deploy from a branch** → Branch 选 `gh-pages` / `(root)` → Save。
   等一两分钟，打开 `https://huangzhenhao90.github.io/urhot/`，点一圈（精选、社招、收藏夹、详情页）确认正常。
7. **最后一步：源码仓库转私有**：Settings → General → Danger Zone → Change repository visibility → Make private。
   同时可以在 Settings → Pages 里关掉旧站点，并删掉 Variable `PAGES_ENABLED`。
8. **转私有之后顺手改两处文案**：
   - 关于页最后写的是「如果你是被收录方并希望调整展示方式，可以通过仓库开 issue 联系」——源码仓库私有后别人开不了 issue。
     换成你想让人联系的方式（邮箱、公众号……）。位置：`web/app/about/page.tsx`。
   - 站点仓库的 README 里写的是「网站地址见 Settings → Pages」，不用改。

### 想保持网址不变（可选）

现在的网址是 `…github.io/ai-ux-research-hot`。想继续用它，就让**站点仓库**叫 `ai-ux-research-hot`，这样 `siteUrl` 一个字都不用改：

1. 先把现在这个源码仓库改名（Settings → General → Repository name），比如 `urhot-src`；
2. 再新建一个公开仓库叫 `ai-ux-research-hot`，按上面 2–7 步做，`PUBLIC_SITE_REPO` 填 `huangzhenhao90/ai-ux-research-hot`。

代价：改名那一刻到新站点上线之间，旧网址会不可用；本地克隆与 Claude 会话里的远程地址要跟着改。所以我没替你做。

**自定义域名**：以后想用自己的域名，在站点仓库的 Pages 设置里填域名，`siteUrl` 改成该域名，
并设置 Variable `PUBLIC_SITE_BASE_PATH` = `/`（站点在域名根目录）。

## 防漏：推送前检查什么

`scripts/check_public_output.py` 在两处自动跑：CI 每次构建之后；Update 每次发布之前。任何一条不过，这次就不发布（数据状态照常保存）：

- **路径**：站点根目录下不能有 `prompts/ config/ uxhot/ scripts/ tests/ eval/ docs/ .github/ .git/` 这些源码目录；
  任何位置不能有 `.py .yaml .yml .jsonl .pem .key`、`.env*`、`jobs.json`、`manual.yaml`、`sources_state.json`、`pyproject.toml` 等文件。
- **内容**：不能有 API key / GitHub token / 私钥的特征，不能出现 `LLM_API_KEY` 这个变量名。
  （专门处理了「URL 里的 `task-…` `ask-…` 被当成 `sk-` 开头的 key」这种误报。）
- **私有备注**：`data/social/manual.yaml` 里每条岗位的 `internal` 备注（谁分享的、截图文件名……）的原文，不能出现在任何产物里。

页面数据里「有哪些字段会发布」也是白名单：条目走 `uxhot/publish/build_site_data.py` 的字段白名单，
社招岗位走 `uxhot/social/public.py`。以后给内部模型加新字段，默认不会漏出去。

## Actions 分钟数（私有仓库会计费）

公开仓库的 Actions 免费；私有仓库在 GitHub Free 套餐下每月 2,000 分钟（Linux）。
按最近 20 次 Update 的运行记录，每次约 2–9 分钟（多数 2–5 分钟），每 4 小时一次、一天 6 次，
**估计每月 700–1,500 分钟**，在额度内但不算宽裕。如果接近上限，把 `update.yml` 里的 `cron` 调疏（比如每 6 小时），
或者在 Settings → Billing 里看实际用量。

## 不想用 GitHub Pages？

站点就是一堆静态文件，Cloudflare Pages、Netlify、Vercel 都能从**私有**仓库免费部署（它们在 GitHub 上装一个应用、授权读源码仓库）。
这样就不需要站点仓库了；构建命令 `cd web && npm ci && npm run build`，输出目录 `web/out`。
但它们的构建环境里没有 Python 流水线产出的最新数据——数据仍要靠 Update 工作流提交回仓库，由它们监听 `main` 的变化重新构建。
需要的话再说，这条路我没替你搭。
