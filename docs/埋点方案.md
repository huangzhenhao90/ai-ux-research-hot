# 埋点方案：各功能的 PV 与 UV（D21）

站点是静态导出、没有后端，访问数据交给第三方统计服务（Umami 或百度统计）。代码里只做一层很薄的封装（`web/lib/track.ts`）：
页面上到处调 `track(事件名, 参数)`，由它转成统计服务认识的调用。

**没配统计服务时什么都不会发生**：不加载任何脚本、不发任何请求、不写任何 cookie（本地开发、PR 预览都是这样）。
访客浏览器开着「请勿跟踪」（Do Not Track）时同样不统计。

## 接入（约 5 分钟，你来做）

统计服务需要你自己注册账号，我没法替你注册。两个任选一个：

**Umami（推荐：能自定义事件、不用 cookie、有免费档〔额度以官网为准〕，也可以自建）**

1. 注册 Umami Cloud → Add website，域名填站点的域名（如 `huangzhenhao90.github.io`）。
2. 复制它给的 **Website ID**（一串 UUID）。
3. 源码仓库 Settings → Secrets and variables → Actions → Variables，新增：
   `ANALYTICS_PROVIDER` = `umami`，`ANALYTICS_ID` = 刚才的 Website ID。
   自建 Umami 的话再加 `ANALYTICS_HOST` = 你的 Umami 地址（如 `https://stats.example.com`）。
4. 等下一次 Update 构建（或手动跑一次），统计就生效了。Website ID 本来就会出现在页面里，不是密钥，放 Variables 即可。

**百度统计（境内访问更稳，口径就叫 PV / UV）**

1. 注册 → 新增网站 → 获取代码，里面有一行 `hm.baidu.com/hm.js?` 后面跟着一串字符。
2. Variables：`ANALYTICS_PROVIDER` = `baidu`，`ANALYTICS_ID` = 那串字符。

> 代码按两家文档里的用法写，并用「按文档行为写的替身脚本」在真实浏览器里验证过每个事件都发出、
> 页面浏览不会多记或漏记；**还没有对着真实的 Umami / 百度统计账号测过**。接入后建议自己点一圈，
> 到统计后台确认数字在涨。

## 功能与指标对照

**PV = 事件次数，UV = 触发过该事件的人数（统计服务按匿名访客去重）。**
每次换页会发一个 `feature_view` 事件，参数 `feature` 就是功能名；详情页按类型归并（不按具体某篇拆开）。
所以「某个功能的 PV / UV」= 看 `feature_view` 里这个 `feature` 的事件数与访客数。

| 功能 | `feature` | 页面 |
|---|---|---|
| 精选 | `home` | `/` |
| 全部动态 | `all` | `/all/` |
| 主题（列表 / 某个主题） | `topics` / `topics_detail` | `/topics/`、`/topics/<slug>/` |
| 分类页 | `category` | `/category/<key>/` |
| 搜索 | `search` | `/search/` |
| 资讯详情 | `item_detail` | `/item/<id>/` |
| 用研校招（列表 / 岗位详情） | `campus` / `campus_detail` | `/campus/`、`/campus/<id>/` |
| 用研社招（列表 / 岗位详情） | `social` / `social_detail` | `/social/`、`/social/<id>/` |
| 收藏夹 | `favorites` | `/favorites/` |
| 关于 | `about` | `/about/` |

统计服务自带的「页面浏览」报告按真实路径统计，想看具体哪几篇资讯、哪几个岗位最热，看那里。

## 事件清单

参数顺序即百度统计里「操作 / 标签」的顺序（百度的事件是 类别 / 操作 / 标签：类别 = 事件名，操作 = 第一个参数，标签 = 其余参数用 `|` 连起来）。

| 事件 | 参数 | 什么时候发 |
|---|---|---|
| `feature_view` | `feature` | 进入某个功能页（每次换页一次） |
| `bookmark` | `action`(add / remove)、`kind`(item / social / campus)、`where`(card / detail / favorites) | 收藏、取消收藏 |
| `favorites` | `action`(export / import / clear) | 收藏夹里的备份与清空 |
| `search` | `scope`(feed_bar / search_page / social / campus)、`found`(有无结果) | 输入停顿 0.8 秒后记一次；**不记关键词**；信息流顶部搜索框是提交时记一次（不带 `found`） |
| `filter` | `tab`(feed / social / campus / favorites)、`by`(category / date / age / origin / company / city / industry / type / ai / multi / scope / view / kind) | 点筛选；从链接恢复筛选不算 |
| `outbound` | `kind`(item_origin / job_apply / careers_site / favorite_link)、`tab` | 点站外链接（原文、官方投递、公司招聘官网） |
| `load_more` | `tab` | 点「加载更多」 |
| `theme` | `theme`(dark / system / light) | 切换外观 |
| `rss` | `where`(sidebar / footer / home / about) | 点 RSS 订阅 |

服务端渲染的链接不用写 JS，直接加属性就能埋点：`data-track="outbound" data-track-kind="item_origin" data-track-tab="feed"`，
`components/Analytics.tsx` 里有一个统一的点击监听把 `data-track-*` 转成参数。新加埋点时：在 `lib/track.ts` 顶部的清单里补一行，再用这两种方式之一发出去。

## 在统计后台怎么看

界面名称以统计服务当前版本为准：

- **Umami**：Pageviews / Visitors 看整体；Events 里点 `feature_view` → 按属性 `feature` 拆开，就是各功能的 PV（事件数）与 UV（访客数）；其他事件同理。
- **百度统计**：事件分析（事件跟踪）里，类别 = `feature_view`，操作 = 功能名；事件总数 ≈ PV，唯一身份访客数 ≈ UV。

## 隐私与口径

- 不记录：搜索关键词、标题、任何能认出个人的信息。收藏只在读者自己的浏览器里，不上报内容。
- Umami 不用 cookie；**百度统计会设 cookie**。面向境内读者时，关于页「收藏与统计」那一段已经写明统计了什么、不统计什么，用百度统计的话它会自动写出服务名。
- UV 的口径由统计服务决定（Umami 按匿名会话，百度按 cookie）：同一个人换设备、换浏览器、清 cookie 会算多个。
- 广告拦截器会拦掉统计脚本，数字会比真实访问偏低；RSS 阅读器抓取不执行 JS，不计入。
- 站内页面浏览不会因为「筛选条件写进链接」而重复计数（Umami 默认会盯着 `history.replaceState`，所以这里关掉了它的自动页面浏览，改成按换页手动发）。
